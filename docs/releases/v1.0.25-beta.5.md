# Yomikura v1.0.25-beta.5

[Published beta prerelease](https://github.com/Yumekaz/Yomikura/releases/tag/v1.0.25-beta.5), released on 4 November 2026 after owner approval. The tagged packages, checksums, updater signatures and exact installed Windows asset passed the checks below. The stable release remains v1.0.24.

## Install or update on Windows

1. Download `Yomikura_1.0.25-beta.5_x64-setup.exe` and `SHA256SUMS-windows-latest.txt` from this release. Check the installer against the checksum file.
2. If you already use Yomikura, make a backup in **Settings → Backups**, then close the app. Keep your existing library data folder. The tested in-place setup paths are **Do not uninstall** when upgrading and **Add/Reinstall components** when replacing an earlier candidate with the same version.
3. Open the desktop or Start Menu shortcut. New users choose **Set up my library** and follow the guided setup. Yomikura obtains verified Java and Suwayomi components when needed; there is no manual Java or server installation in the recommended desktop path.
4. Choose a source repository you trust, review its publisher information, install a source, then find a comic and open a chapter. Yomikura includes no third-party source content.

For browser use, choose **Read the browser setup guide** on the welcome screen. The illustrated guide explains installing and starting Suwayomi, connecting your library, choosing sources and reading. An existing Suwayomi library can be connected directly. Suwayomi must remain reachable while using features whose data is on that server.

## Changes in this candidate

- Returning readers enter Library directly while the managed local engine starts in the background. No online/offline choice is required.
- Previously retained library titles, categories, viewed comic details and covers remain browsable during an outage. Downloaded chapters open normally; unsaved pages still need a connection.
- Extension-update discovery has in-app notices, counts and a review list, with explicit individual and bulk updates.
- History remembers reading independently of library membership. An outlined heart lets readers add a comic and choose categories.
- Adding a source's alternate version surfaces possible duplicates with source details, **Show entry**, **Add anyway**, **Copy** and **Migrate**. Transfer review lets readers choose chapter state and categories; existing verification safeguards protect the original entry.
- The browser setup guide provides four illustrated steps, official links, a working connection form, storage explanations and connection recovery.
- Clear last-known-chapter status, zoom shared across pages with reset, reliable source-page opening and constrained detail-page layout.
- Desktop source, help and update links use a shared validated browser handoff with failure recovery.
- Server-update notices remain readable in all light palettes and explain managed-engine versus remote-server updates.
- Palette-aware chapter endings and built-in tracker symbols that stay visible without remote logos. Desktop shortcut reopening also requests restoration of a minimized window; its final installed check is recorded below.

## Update channels and known limits

- Beta installers are downloaded manually from their release page. Automatic update checks follow the latest stable release, so an up-to-date message does not discover every preview. The website's normal desktop-download button also follows stable releases; use this specific beta release page to obtain this preview.
- Windows installers do not yet have Authenticode publisher signing. Updater signatures verify payload identity separately from Windows publisher trust. macOS signing/notarization and interactive Linux/macOS testing have separate limits.
- The managed runtime and real-server verification use Suwayomi v2.3.2243. Other remote server versions require their own compatibility checks; a newer upstream version is not installed automatically over the managed library.
- Extension notifications work inside Yomikura while it is open; this version does not add a closed-app notification service.
- Disconnected browsing uses metadata and covers retained after successful reads. Unseen data cannot be reconstructed during an outage. Browser/device storage can be cleared or evicted, so retained metadata is not a backup.
- Metadata backups do not include downloaded comic page bytes. Preserve your data folder and export important notes when changing installations.
- Duplicate title matching identifies possible matches rather than proving that two works are identical. Downloaded page bytes are not moved between sources.
- Known [library identity limits](../LIBRARY_IDENTITY_2026-11-02.md) remain: identical copied markers cannot be distinguished automatically, client preflight is not an atomic cross-client transaction, and abrupt upstream termination has not established crash-durable metadata.
- Signed-in tracker providers, spoken screen-reader output, other physical hardware and a forward stable automatic-update installation require separate evidence.

Report a reproducible problem through **Settings → About → Report a bug**. Keep credentials, private server addresses, personal screenshots and library archives out of public reports.
