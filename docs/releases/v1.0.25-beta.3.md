# Yomikura v1.0.25-beta.3

This Windows beta brings the reading-room redesign and reliability work together. It is intended for readers who want a local Suwayomi library with guided setup, saved chapters and recoverable progress.

## Install or update on Windows

1. Download `Yomikura_1.0.25-beta.3_x64-setup.exe` and `SHA256SUMS-windows-latest.txt` from this release. Check the installer hash against the checksum file.
2. Close Yomikura before running the installer. For an existing library, make a backup from Settings → Backups first. Keep the existing data folder when updating.
3. Open Yomikura from the desktop or Start Menu shortcut. New installations can use **Set up my library**; an existing library can be connected separately. Guided setup obtains verified Java and Suwayomi components when required.
4. Add a source repository you trust, install the source you want, then find a comic and open a chapter. Source repositories and their content are operated independently of Yomikura.

Windows installers are currently unsigned for Windows publisher trust. Tauri updater signatures authenticate update payloads separately; they do not establish SmartScreen trust. Do not bypass a security warning without reviewing the downloaded file and publisher information yourself.

Preview builds follow the stable automatic-update feed. Download later beta installers manually from Releases; a stable-channel update check does not discover every preview.

## Changes

- Ink & Ember identity, original reading-spirit artwork, consistent in-app branding, complete light/dark palettes and theme customization.
- More compact library controls, readable covers, useful continuation, clearer navigation and themed dropdowns.
- One latest history entry per comic, first-unread chapter resume, improved chapter actions, keyboard focus and reader restoration.
- Library filters and collections, source preferences, reader controls, reading insights and desktop equivalents informed by Mihon's behavior.
- Retained, verified backups and a safety copy before restore. Backup origin labels distinguish matching, different and unverified library data.
- Library-scoped progress, notes, device chapters and download jobs. Earlier or unverified work stays available for review rather than silently replaying into another library.
- Pending progress persists through outages and restarts. Restore recovery pauses local writes until the result is confirmed and renews the library marker.
- Offline recent reading retains the actual last position while directing users to saved chapters when that latest chapter is unavailable. Reader connection errors use theme-aware, reader-focused recovery.
- Reconnecting refreshes chapter continuation without resetting the active page. Failed downloads retain readable comic/chapter labels; saved-size summaries describe the selected library.
- Statistics remains reachable in compact windows, with readable active navigation in light mode.
- Release drafts include flat downloadable checksum manifests and signature verification against the configured updater key.

## Verification boundaries

The [beta verification report](../BETA_VERIFICATION_2026-11-03.md) records exact commits, GitHub runs, installer provenance, installed-app checks and failed attempts. Its final status is the source of truth for review.

Windows has direct installed-app testing. Linux/macOS packaging does not establish equivalent interactive validation. Signed-in tracking-provider journeys, every third-party source and an end-to-end forward automatic update are not covered by the Windows reading checks.

A copied Suwayomi database can carry the same client marker. Known copies can be separated explicitly in Connection settings; identical clones cannot be detected automatically. Client checks do not provide atomic cross-client writes or guarantee upstream metadata durability after a sudden termination.

Downloaded page bytes are device data; they are not included in a Suwayomi metadata backup. Preserve the selected data directory and export important notes before changing installations.

Report reproducible problems through Settings → About → Report a bug. Keep credentials, private server addresses, personal screenshots and full library archives out of public reports.
